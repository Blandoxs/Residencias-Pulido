====================================================================
 SIGEV - Instalacion y puesta en marcha
 Sistema de Gestion de Equipo y Vigencias
 Comision Federal de Electricidad - Zona Parral, Chihuahua
====================================================================

Esta guia lleva paso a paso desde una computadora sin nada instalado
hasta el sistema funcionando y visible para los demas dispositivos de
la red.

Todos los comandos se escriben en la consola de Windows (CMD o
PowerShell). En el ANEXO, al final, estan todos juntos para copiar y
pegar de corrido.


--------------------------------------------------------------------
 DOS VERSIONES: CUAL ES CUAL
--------------------------------------------------------------------

  1. DEMOSTRACION (solo para verla, no guarda nada de verdad)

     https://blandoxs.github.io/Residencias-Pulido/

     Se abre en cualquier navegador con internet, sin instalar nada.
     Los datos son de ejemplo y viven en el navegador de quien la abre.
     Sirve para mostrar el sistema; no para trabajar con el.
     Se entra con: admin / admin

  2. SISTEMA REAL (el que se instala y guarda la informacion)

     Es el de esta guia. Corre en una computadora de la oficina, guarda
     todo en su propia base de datos y los demas equipos lo abren por
     la red. Codigo:

     https://github.com/Blandoxs/Residencias-Pulido


--------------------------------------------------------------------
 QUE SE NECESITA
--------------------------------------------------------------------

  - Windows 10 o superior
  - Node.js 22.5 o mas nuevo   (PASO 1)
  - Git                        (PASO 2)
  - Que el equipo este conectado a la misma red (Wi-Fi o cable) que
    los dispositivos que lo van a usar

NO se necesita instalar base de datos, servidor web, XAMPP ni Apache: el
sistema usa lo que ya trae Node.js. La unica libreria externa es
nodemailer, para los correos de aviso, y se instala con un solo comando
en el PASO 3.


--------------------------------------------------------------------
 PASO 1 - INSTALAR NODE.JS
--------------------------------------------------------------------

Revise primero si ya lo tiene. Abra la consola y escriba:

    node -v

Si responde algo como  v24.12.0  (el numero debe ser 22 o mayor), ya
esta instalado y puede pasar al PASO 2.

Si dice que no reconoce el comando, instalelo:

  OPCION A - Desde la consola (mas rapido):

    winget install OpenJS.NodeJS.LTS

  OPCION B - Descargandolo:

    1. Entre a   https://nodejs.org
    2. Descargue la version LTS para Windows
    3. Ejecute el instalador y acepte todas las opciones por omision

IMPORTANTE: al terminar, CIERRE la consola y abra una nueva. Si no, el
comando node sigue sin reconocerse.

Compruebe:

    node -v
    npm -v


--------------------------------------------------------------------
 PASO 2 - INSTALAR GIT
--------------------------------------------------------------------

Git es lo que permite descargar el proyecto y, mas adelante, traer las
actualizaciones sin volver a copiar carpetas a mano.

Revise si ya lo tiene:

    git --version

Si responde algo como  git version 2.51.0.windows.1 , pase al PASO 3.

Si no lo reconoce, instalelo:

  OPCION A - Desde la consola:

    winget install Git.Git

  OPCION B - Descargandolo:

    1. Entre a   https://git-scm.com/download/win
    2. Descargue "64-bit Git for Windows Setup"
    3. Ejecute el instalador y acepte todas las opciones por omision

Otra vez: CIERRE la consola y abra una nueva al terminar.

Compruebe:

    git --version


--------------------------------------------------------------------
 PASO 3 - DESCARGAR EL PROYECTO
--------------------------------------------------------------------

Elija donde va a vivir el sistema. En esta guia se usa C:\SIGEV

    cd C:\
    git clone https://github.com/Blandoxs/Residencias-Pulido.git SIGEV

Eso crea la carpeta C:\SIGEV con todo el proyecto adentro. Entre a
ella (este comando se usa cada vez que se va a encender el sistema):

    cd C:\SIGEV

Compruebe que se descargo bien: debe listar server.js, package.json,
las carpetas src y public, y este mismo archivo.

    dir

Instale la unica dependencia del proyecto (nodemailer, la libreria que
manda los correos de aviso):

    npm install

El sistema funciona igual sin este paso: lo unico que no podria hacer es
enviar correos. Todo lo demas (base de datos, alertas dentro del sistema,
pantallas) usa lo que ya trae Node.js.

Para traer actualizaciones mas adelante, estando dentro de C:\SIGEV:

    git pull

(La base de datos NO se toca al actualizar: vive en la carpeta datos\,
que git ignora a proposito.)


--------------------------------------------------------------------
 PASO 4 - PRIMER ARRANQUE Y CONTRASENA
--------------------------------------------------------------------

Solo la primera vez, arranquelo asi:

    npm start

En la consola aparecera la contrasena del administrador. SE MUESTRA UNA
SOLA VEZ:

    ***********************************************************
     ACCESO INICIAL (se muestra una sola vez)
       Usuario:    admin
       Contrasena: xxxxxxxxxxxxxx
    ***********************************************************

Tambien queda guardada en el archivo  datos\acceso-inicial.txt

Abra el sistema en este equipo:

    http://localhost:3000

Entre con el usuario admin y esa contrasena. Lo PRIMERO que debe hacer
es cambiarla: menu de su nombre (arriba a la derecha) -> Cambiar
contrasena. Despues borre el archivo datos\acceso-inicial.txt.

Si en algun momento se pierde esa contrasena, se restablece desde la
consola del propio equipo:

    npm run clave -- admin MiContrasenaNueva

Para detener el servidor: presione   Ctrl + C   en la consola.


--------------------------------------------------------------------
 PASO 5 - ENCENDERLO PARA TODA LA RED
--------------------------------------------------------------------

Este es el comando que se usa de aqui en adelante:

    npm run red

La diferencia con  npm start  es que este escucha en toda la red, no
solo en el equipo. Al arrancar muestra la direccion exacta:

    ============================================================
     SIGEV  |  Sistema de Gestion de Equipo y Vigencias  |  CFE
    ============================================================
     En este equipo:  http://localhost:3000
     Desde otros dispositivos de la misma red:
       http://192.168.0.5:3000   (Wi-Fi)
     Base de datos:   C:\SIGEV\datos\sigev.db
    ------------------------------------------------------------

Anote esa direccion: es la que se escribe en los demas dispositivos.
La suya puede ser distinta a 192.168.0.5.

La consola debe quedarse abierta mientras el sistema este en uso. Se
puede minimizar, pero si se cierra, el sistema se apaga.

Tambien se puede encender con doble clic en el archivo:

    INICIAR-SIGEV.bat


--------------------------------------------------------------------
 PASO 6 - PERMITIR EL PUERTO EN EL FIREWALL (UNA SOLA VEZ)
--------------------------------------------------------------------

Windows bloquea por omision las conexiones que llegan de otros equipos.
Sin este paso, el sistema abre en esta computadora pero NO en las demas.

Abra la consola COMO ADMINISTRADOR:

    Menu Inicio -> escriba: powershell
    -> clic derecho en Windows PowerShell -> "Ejecutar como administrador"

Y pegue este comando (es una sola linea):

    netsh advfirewall firewall add rule name="SIGEV (puerto 3000)" dir=in action=allow protocol=TCP localport=3000 profile=any

Debe responder:  Aceptar.

Ademas, si la red de este equipo esta marcada como "Publica", Windows
restringe aun mas. Conviene marcarla como privada (misma consola de
administrador; cambie Wi-Fi por Ethernet si usa cable):

    Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Private

Para revisar como quedo:

    Get-NetConnectionProfile

Para quitar el permiso mas adelante (si se deja de usar):

    netsh advfirewall firewall delete rule name="SIGEV (puerto 3000)"


--------------------------------------------------------------------
 PASO 7 - ENTRAR DESDE LOS DEMAS DISPOSITIVOS
--------------------------------------------------------------------

En el telefono o en otra computadora, conectados a la MISMA red:

  1. Abra el navegador (Chrome, Edge, Safari)
  2. Escriba la direccion que mostro la consola, por ejemplo:

        http://192.168.0.5:3000

  3. Entre con su usuario y contrasena

Nota: escriba http:// al inicio. Si solo pone la IP, algunos telefonos
la toman como busqueda en Google.

Cada persona entra con su propia cuenta. Las cuentas se dan de alta
desde el sistema: seccion 04 Administracion -> Usuarios, eligiendo su
perfil:

    Administrador             ve y administra todo el sistema
    Jefe de Seguridad         Extintores y Equipo de Seguridad
    Encargado de Documentacion   Gafetes y Licencias

Los tres ven Panel, Vigencias, Alertas y Personal.


--------------------------------------------------------------------
 PASO 8 - QUE EL SERVIDOR ARRANQUE SOLO (RECOMENDADO)
--------------------------------------------------------------------

Hasta aqui, el sistema se enciende a mano y se apaga cuando se cierra la
ventana. En un equipo que va a estar dando servicio conviene que se
encienda solo.

  OPCION A - Al iniciar sesion (no necesita permisos de administrador)

    npm run autoarranque

  Eso coloca un acceso directo en la carpeta de Inicio de Windows. A
  partir de ahi, cada vez que alguien inicie sesion en este equipo, SIGEV
  se enciende solo en una ventana minimizada.

  Para desactivarlo:

    npm run autoarranque -- -quitar

  Para ver si esta activado, abra la carpeta de Inicio:

    explorer shell:startup

  (debe aparecer un acceso directo llamado SIGEV)

  OPCION B - Con la computadora encendida, aunque nadie inicie sesion

  Sirve cuando el equipo se queda prendido como servidor y no se le
  inicia sesion. Necesita consola COMO ADMINISTRADOR y que se escriba la
  ruta real de la carpeta:

    schtasks /create /tn "SIGEV" /tr "C:\SIGEV\INICIAR-SIGEV.bat" /sc onstart /ru SYSTEM /rl highest /f

  Para comprobarla, iniciarla a mano o quitarla:

    schtasks /query  /tn "SIGEV"
    schtasks /run    /tn "SIGEV"
    schtasks /delete /tn "SIGEV" /f

COMO SABER SI ESTA ENCENDIDO

  Desde el propio equipo, abra   http://localhost:3000
  O desde la consola:

    curl http://localhost:3000

  Si responde el HTML de la pagina, esta encendido. Si dice que no se
  pudo conectar, esta apagado.

IMPORTANTE: el equipo no debe suspenderse ni apagarse mientras se use el
sistema. En Configuracion de Windows -> Sistema -> Inicio y apagado,
ponga "Suspender" en Nunca cuando este conectado a la corriente.

--------------------------------------------------------------------
 INSTALARLO EN OTRA COMPUTADORA
--------------------------------------------------------------------

El sistema no esta amarrado a este equipo. Para dejarlo corriendo en
otra computadora (por ejemplo la del area de Seguridad e Higiene, o un
equipo que se quede encendido como servidor):

 1. En la computadora NUEVA, repita los PASOS 1 al 6 de esta guia:
    Node.js, Git, clonar el proyecto, npm install, primer arranque y la
    regla del firewall.

 2. Tres cosas cambian y hay que revisarlas:

    LA DIRECCION. Cada computadora tiene la suya. NO use 192.168.0.5:
    esa es la de este equipo. La direccion correcta la imprime el propio
    sistema al arrancar con npm run red, o se consulta con:

        ipconfig

    LA CARPETA. En esta guia se usa C:\SIGEV, pero puede ser cualquiera.
    Si la ruta lleva espacios, va entre comillas al hacer cd.

    EL PUERTO. Si el 3000 ya lo ocupa otro programa en ese equipo, use
    otro antes de arrancar:

        set PORT=8080
        npm run red

    Entonces la direccion sera http://<IP-del-equipo>:8080 y la regla
    del firewall debe abrir 8080 en lugar de 3000.

 3. Avise a los usuarios la direccion nueva: es lo unico que escriben en
    el navegador de su telefono o computadora.

LLEVARSE LA INFORMACION DE UN EQUIPO A OTRO

Si ya se venia trabajando en esta computadora y quiere continuar en la
nueva sin perder los registros:

 1. En el equipo VIEJO, detenga el servidor (Ctrl + C).
 2. Copie la carpeta   datos\   completa a una USB.
 3. En el equipo NUEVO, con el servidor detenido, pegue esa carpeta
    dentro del proyecto, reemplazando la que se creo sola.
 4. Encienda con npm run red.

Se lleva todo: personal, gafetes, extintores, equipo, licencias,
usuarios, alertas y bitacora. Las contrasenas siguen siendo las mismas
porque viajan cifradas dentro de ese archivo.

UNA SOLA COMPUTADORA GUARDA LA INFORMACION

Esto es importante: si dos computadoras corren SIGEV al mismo tiempo, NO
comparten datos. Serian dos sistemas independientes, cada uno con su
propia base, y lo que se capture en uno no aparece en el otro.

Elija UN equipo como servidor. Los demas NO instalan nada: solo abren la
direccion en el navegador.


--------------------------------------------------------------------
 QUE LA DIRECCION NO CAMBIE (RECOMENDADO)
--------------------------------------------------------------------

La IP del equipo puede cambiar al reiniciar el modem, y entonces los
demas dispositivos ya no lo encontrarian en la misma direccion. Para
evitarlo hay dos caminos:

  1. Pedirle al area de redes que reserve una IP fija para este equipo
     (es lo correcto en la instalacion de CFE), o

  2. Configurar IP fija en Windows:
     Configuracion -> Red e Internet -> Wi-Fi (o Ethernet) ->
     Propiedades -> Configuracion IP -> Editar -> Manual

Si la IP cambia, no se pierde nada: solo hay que volver a leer la
direccion que muestra la consola al arrancar y usar la nueva.


--------------------------------------------------------------------
 RESPALDO DE LA INFORMACION
--------------------------------------------------------------------

Toda la informacion vive en un solo archivo:

    C:\SIGEV\datos\sigev.db

Para respaldar: DETENGA el servidor (Ctrl + C) y copie la carpeta
datos\ completa a una USB o carpeta de red. Para restaurar, reemplace
esa carpeta y vuelva a encender.

Se recomienda respaldar una vez por semana.


--------------------------------------------------------------------
 CORREO DE AVISOS (OPCIONAL)
--------------------------------------------------------------------

El sistema avisa dentro de la aplicacion sin ninguna configuracion
extra. Para que ademas mande correos hacen falta tres cosas:

  1. La libreria, que ya viene declarada en el proyecto. Si ejecuto
     npm install en el PASO 3, ya esta. Si no:

         npm install

  2. Los datos del servidor SMTP institucional, en la MISMA consola
     desde la que se va a arrancar el sistema:

         set SMTP_HOST=smtp.cfe.mx
         set SMTP_PORT=587
         set SMTP_USER=alertas.parral@cfe.mx
         set SMTP_PASS=la_contrasena_real
         set SMTP_FROM=SIGEV CFE <alertas.parral@cfe.mx>
         set SMTP_SEGURO=false
         npm run red

     (SMTP_SEGURO=true solo si el servidor usa el puerto 465.)

     Estos datos los proporciona el area de TICS. Las contrasenas NUNCA
     se escriben dentro de los archivos del proyecto ni se suben al
     repositorio: viven solo en la consola del servidor.

  3. Activarlo dentro del sistema: entrar como Administrador ->
     Configuracion -> el campo "Envio de alertas por correo" pasa de
     "Desactivado (solo en el sistema)" a "Activado (requiere SMTP)".
     En esa misma pantalla se captura el correo del administrador, que
     recibe copia de todas las alertas.

COMO COMPROBAR QUE FUNCIONA:

  a. Que los trabajadores y los usuarios tengan correo capturado
     (Personal y Usuarios).
  b. Bajar temporalmente el aviso de un tipo de elemento en
     Configuracion -> Anticipacion por tipo, para provocar una alerta.
  c. Presionar "Revisar" en el Panel. Abajo aparece cuantos correos se
     enviaron.
  d. Revisar la bandeja del trabajador, la del encargado del modulo y la
     del administrador: a los tres les debe llegar.

Si algo falla, el sistema NO se detiene: anota el motivo (por ejemplo
"SMTP no configurado") y conserva la alerta dentro del sistema.


--------------------------------------------------------------------
 PROBLEMAS COMUNES
--------------------------------------------------------------------

 "node no se reconoce como comando"
     No se instalo Node.js, o no se cerro y volvio a abrir la consola
     despues de instalarlo. Vea el PASO 1.

 "git no se reconoce como comando"
     Lo mismo con Git: vea el PASO 2 y abra una consola nueva.

 "Error: listen EADDRINUSE ... 3000"
     El puerto ya esta ocupado, casi siempre porque el sistema ya estaba
     encendido en otra ventana. Cierre esa ventana, o use otro puerto:

         set PORT=3001
         npm run red

 Abre en esta computadora pero no en el telefono
     1. Falta la regla del firewall (PASO 6)
     2. El telefono esta en otra red (datos moviles, o una Wi-Fi de
        invitados que aisla los dispositivos)
     3. Se escribio la direccion sin http:// al inicio

 Olvide la contrasena del administrador
     Se restablece desde la consola del propio equipo, dentro de la
     carpeta del proyecto:

         npm run clave -- admin MiContrasenaNueva

     Para ver que cuentas existen, ejecutelo sin datos:

         npm run clave

     Solo funciona con acceso fisico al equipo y al archivo de la base
     de datos; no se puede hacer desde la red. Aun asi, conviene tener
     dos cuentas con perfil Administrador.

 La pagina se ve pero dice "Modo demostracion"
     Eso es la version de exhibicion publicada en internet, no el
     sistema real. El sistema real es el que arranca con npm run red y
     guarda en datos\sigev.db.
